# TaskX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-window desktop app that lists projects by manual priority and shows, per project, what was done last and what to do next.

**Architecture:** Electron main process owns the JSON file through a small pure `store.js` module; the renderer gets exactly three IPC channels through a `preload.js` bridge and never touches `fs`. Renderer is plain JavaScript with no build step.

**Tech Stack:** Electron, CommonJS, vanilla HTML/CSS/JS, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-29-taskx-design.md`

## Global Constraints

- No runtime dependencies beyond Electron. Dev dependency: `electron` only.
- CommonJS everywhere (`require` / `module.exports`). No `"type": "module"`, no bundler, no TypeScript.
- Renderer is loaded with a plain `<script src="app.js">`; no ES modules in the renderer.
- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. No `shell`, no remote content, no navigation.
- Storage file: `path.join(app.getPath('userData'), 'data.json')`. Written atomically: write `<file>.tmp`, then rename over `<file>`.
- Data shape (exact keys): `{ version: 1, projects: Project[] }`, `Project = { id: string, name: string, priority: number, last: string, next: string, updatedAt: number }`.
- Sorting is by `priority` ascending, never by date or name.
- Every edit persists immediately. There is no Save button.
- Window 760×560, resizable, single instance.

## Review Focus

1. `data.json` corrupt or hand-edited — app must open with an empty list, not a white screen or a crash.
2. Non-ASCII text (Arabic, emoji, accents) in `name`/`last`/`next` — must survive save and reload byte-identical.
3. Empty or whitespace-only `name` — the row must still be visible and editable, not collapse to nothing.
4. Very long `next` text (500+ chars) — must not break the layout or push the reorder buttons off-screen.
5. Crash or kill mid-save — `data.json` must never be truncated to zero bytes.

### Task 1: Store

**Files:**
- Create: `package.json`, `.gitignore`, `store.js`
- Test: `test/store.test.js`

**Interfaces:**
- Produces:
  - `createStore(filePath: string)` → `{ load(): Doc, save(doc: Doc): void, move(doc: Doc, id: string, direction: 'up' | 'down'): Doc }`
  - `Doc = { version: 1, projects: Project[] }`
  - `load()` returns `{ version: 1, projects: [] }` when the file is missing **or** unparseable, and never throws.
  - `save(doc)` writes `<filePath>.tmp` then renames over `filePath`; leaves no `.tmp` behind.
  - `move(doc, id, direction)` sorts by `priority`, swaps the neighbour, renumbers every project `0..n-1`, returns the same doc mutated. At a boundary it renumbers and changes nothing else.

- [ ] **Step 2: Write the failing tests**

`test/store.test.js`:

```js
const { test } = require('node:test');
const assert = require('node:assert');
const fs = require('node:fs');
const os = require('node:os');
const path = require('node:path');
const { createStore } = require('../store.js');

function tmpFile() {
  return path.join(fs.mkdtempSync(path.join(os.tmpdir(), 'taskx-')), 'data.json');
}

const project = (id, priority) => ({
  id, name: id, priority, last: '', next: '', updatedAt: 0,
});

test('load returns an empty doc when the file is missing', () => {
  assert.deepStrictEqual(createStore(tmpFile()).load(), { version: 1, projects: [] });
});

test('save then load round-trips projects', () => {
  const store = createStore(tmpFile());
  const doc = { version: 1, projects: [project('a', 0), project('b', 1)] };
  store.save(doc);
  assert.deepStrictEqual(store.load(), doc);
});

test('save leaves no .tmp file behind', () => {
  const file = tmpFile();
  createStore(file).save({ version: 1, projects: [] });
  assert.strictEqual(fs.existsSync(file + '.tmp'), false);
  assert.strictEqual(fs.existsSync(file), true);
});

test('load returns an empty doc for corrupt JSON instead of throwing', () => {
  const file = tmpFile();
  fs.writeFileSync(file, '{ not json');
  assert.deepStrictEqual(createStore(file).load(), { version: 1, projects: [] });
});

test('non-ASCII text survives a round trip', () => {
  const store = createStore(tmpFile());
  const p = { ...project('a', 0), name: 'مشروع', last: 'naïve café', next: '🚀 ship it' };
  store.save({ version: 1, projects: [p] });
  assert.deepStrictEqual(store.load().projects[0], p);
});

test('move up renumbers priorities sequentially', () => {
  const doc = { version: 1, projects: [project('a', 0), project('b', 1), project('c', 2)] };
  const out = createStore(tmpFile()).move(doc, 'c', 'up');
  assert.deepStrictEqual(out.projects.map(p => [p.id, p.priority]), [['a', 0], ['c', 1], ['b', 2]]);
});

test('move past the top edge is a no-op', () => {
  const doc = { version: 1, projects: [project('a', 0), project('b', 1)] };
  const out = createStore(tmpFile()).move(doc, 'a', 'up');
  assert.deepStrictEqual(out.projects.map(p => p.id), ['a', 'b']);
});
```

### Task 2: Electron shell and IPC

**Files:**
- Create: `main.js`, `preload.js`

**Interfaces:**
- Consumes: `createStore(filePath)` from Task 1.
- Produces: `window.taskx` in the renderer:
  - `load(): Promise<Doc>`
  - `save(doc: Doc): Promise<void>`
  - `move(id: string, direction: 'up' | 'down'): Promise<Doc>`
- IPC channel names: `data:load`, `data:save`, `data:move`.

- [ ] **Step 1: Implement `preload.js`**

`contextBridge.exposeInMainWorld('taskx', { load, save, move })`, each an `ipcRenderer.invoke` call on the channel names above. Nothing else is exposed.

- [ ] **Step 2: Implement `main.js`**

- Single store created once with `path.join(app.getPath('userData'), 'data.json')`.
- `app.requestSingleInstanceLock()`; a second launch focuses the existing window.
- `BrowserWindow({ width: 760, height: 560, webPreferences: { preload, contextIsolation: true, nodeIntegration: false, sandbox: true } })`.
- `ipcMain.handle` for the three channels; `data:move` loads, moves, saves, returns the new doc.
- `window-all-closed` → `app.quit()` on win32.

- [ ] **Step 3: Verify the window opens**

Run: `npm start`
Expected: a 760×560 blank window opens and `window.taskx` exists in devtools console (`Object.keys(window.taskx)` → `['load','save','move']`).

- [ ] **Step 4: Commit**

```bash
git add main.js preload.js
git commit -m "feat(shell): electron window with three IPC channels"
```

### Task 3: Renderer

**Files:**
- Create: `renderer/index.html`, `renderer/style.css`, `renderer/app.js`

**Interfaces:**
- Consumes: `window.taskx.load/save/move` from Task 2.
- Produces: the UI described in the spec's "Screen" section.

- [ ] **Step 1: Implement `index.html`**

`<input data-field="name">`, `<input data-field="last">`, `<input data-field="next">` per row, `↑`/`↓`/`×` buttons per row, one `+ Add project` button, one `#empty` line. Plain `<script src="app.js"></script>` at the end of body.

- [ ] **Step 2: Implement `app.js`**

- `let doc` loaded once on start via `taskx.load()`.
- `render()` rebuilds the list from `doc.projects` sorted by `priority`.
- Inputs are always editable. Bind `change` (blur/Enter) → update the field, `updatedAt = Date.now()`, `taskx.save(doc)`. No Save button.
- `+ Add project` appends `{ id: crypto.randomUUID(), name: '', priority: doc.projects.length, last: '', next: '', updatedAt: Date.now() }`, saves, re-renders, focuses the new name input.
- `↑`/`↓` → `doc = await taskx.move(id, dir)` then `render()`.
- `×` → `confirm('Delete this project?')`, filter, save, render. Skip the confirm when `name` is empty.
- Empty list → show `#empty` ("Add your first project."), hide the list.
- Long text: `next` input is a single-line `<input>` with `text-overflow: ellipsis`; nothing wraps or grows.

- [ ] **Step 3: Implement `style.css`**

System font stack. Flat list with hairline separators, no shadows or cards. Priority-0 row gets a 3px left accent bar and `font-weight: 600` on the name. Buttons are text-sized and unfilled. Background `#fbfbfa`, text `#1a1a1a`.

- [ ] **Step 4: Verify the golden path by hand**

Run: `npm start`. Add two projects, give each a `last` and a `next`, reorder, delete one.
Expected: every change is visible immediately and no console errors appear.

- [ ] **Step 5: Commit**

```bash
git add renderer/
git commit -m "feat(ui): single-screen project list with inline editing"
```
